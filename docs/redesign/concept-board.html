Concept board · Adyansh Gupta portfolio · 3 September 2026 · branch redesign-3d

Three directions for a robotics portfolio that feels like a robot built it

The facts stay exactly as they are: ten projects, six roles, three hackathon results, one paper, two patents, three certifications, two degrees, the résumé and the chat assistant. Everything else is on the table. Each direction below turns one of Adyansh's real specialties into the mechanic that holds the whole site together, instead of decorating a card stack with neon.

Why the current site reads as "basic". It is a vertical stack of glass cards with a green glow, glitch text, and a stock Spline humanoid that is not one of Adyansh's robots. Nothing spatial connects the sections, so the 3D is a poster on the wall rather than the room you are standing in. The fix is not more effects. It is one strong spatial idea that the scroll drives.

Recommendation

Build A, borrow two things

Mission Log is the one where the mechanic is the message. Frontier exploration, zone segmentation, and a docking station are literally what Adyansh shipped for the Go2 hackathon and for OLIVE. A visitor who never reads a word still learns what he does. It is also the direction with the most room to be the best site in its category rather than a very good version of a known pattern.

Two borrowings keep it from being one-note. From C: the tech-tag filter that lights up related projects, and turbo-coloured point clouds as the only place colour carries data. From B: the title-block treatment for project detail sheets, because the CAD lineage deserves one honest nod. The boldness lives in the world and the camera; everything else stays quiet.

Constraints found in the repo

  • Static export to GitHub Pages under /my-portfolio. No server code; the chat already goes through a Cloudflare Worker, so that keeps working.
  • 769 MB of project media sits in public/projects: GIFs of 65 to 95 MB and videos up to 94 MB. GitHub Pages sites are capped near 1 GB, and a phone will never finish loading a 95 MB GIF. Re-encoding to MP4/WebM keeps the content identical and cuts this by roughly 10 to 20 times.
  • One broken file: abu-robocon/Robocon 1.mp4 is 0 bytes.
  • Spline hero loads a stock humanoid from an external URL through a heavy runtime. Replacing it with a model of an actual robot Adyansh worked with is both lighter and truer.
  • Five-colour theme switcher works against a designed palette. Recommendation: commit to one palette per direction and drop it.

The open lane

Robotics companies (Boston Dynamics, Figure, 1X, Unitree, Apptronik) ship video heroes and spec grids, not real-time 3D. Robotics engineers' portfolios that use real URDFs or SLAM demos look like RViz screenshots with no art direction. Nobody found has combined an actual robot model, live telemetry, and award-level design. Direction A sits exactly there.

What now reads as dated

  • Glitch text with no story reason, floating particle backgrounds, multi-speed parallax. The current site uses all three.
  • Hero video or 3D with zero interaction; autoplay audio.
  • Effect stacking instead of one idea; templates with a neon accent swapped in.

Table stakes in 2026: 60 fps on a mid-range phone or a designed fallback, reduced-motion path, compressed assets (Draco or Meshopt, KTX2 textures), rendering paused off-screen.

Research · how to build it on this repo

Tech decisions, checked against what is installed

Scroll and 3D architecture

GSAP ScrollTrigger driving a React Three Fiber canvas pinned with CSS position: sticky, with normal DOM sections in between. GSAP and all its plugins have been free since April 2025. Each section registers a trigger whose progress is written to a ref and read inside the render loop, so React never re-renders per scroll tick. Lenis smooth scroll is optional and only added if plain scrubbing is not smooth enough.

Rejected: drei's ScrollControls (it puts its own scroll container in front of the canvas and fights a Tailwind page), and Framer Motion's scroll hooks as the main engine (fine for one hero, no pin or snap timelines for a six-zone story). WebGPU stays off the table for now: first-class React Three Fiber support is still in alpha, and the drei helpers are partly broken on it. Shaders stay small in GLSL so a later port is cheap.

Robot models

Real robot descriptions load with urdf-loader (Apache-2.0), which gives animatable joints for free. The simpler route for the final build is to bake each robot into one compressed GLB with named joint nodes and rotate those nodes directly, dropping the loader from the bundle. URDF files are Z-up; the scene rotates them once.

Decisions needed

Questions before building

  1. Direction. A, B, C, or the recommended A with borrowings?
  2. Your own robots. Do you have CAD, URDF, STEP or STL files for any robot you built: the Kiwi drive, AgroBot, R2, Vanguard, the rocker-bogie? Real geometry of your machines beats any downloaded model and would be the single biggest differentiator.
  3. Keep or drop. The Spline humanoid, the five-colour theme switcher, and the AI chat assistant. My recommendation: drop the first two, keep and restyle the chat.
  4. Media. May I re-encode the GIFs and videos to compressed MP4/WebM and generate poster frames? Same content, a fraction of the weight. Also: do you have a replacement for the empty Robocon 1 video?
  5. Audience and devices. Recruiters on phones matter? That sets how much of the 3D must degrade gracefully versus being desktop-first.
  6. Themes. Dark only, or dark and light? A and C are dark-first; B is light-first with a blueprint dark mode.
  7. Domain. Staying on GitHub Pages at /my-portfolio, or moving to a custom domain? It changes the base path and lets media move to a CDN.
  8. Which arms. Which robot arm did you use at the RWTH hackathon, and which at Robotics Collective? The models should match the real hardware.
  9. Sound. Subtle, off-by-default UI sound (dock chime, sweep tick) is common on award-level sites. Want it as an option, or never?
